# web-to-local-md 黄金测试集 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create ~50 golden test cases for web-to-local-md, each from a different well-known website, with reference output files for evaluate-skill regression testing.

**Architecture:** Data generation task — create case-* directories with input.yaml (URL + metadata) and reference/ (web-to-local-md output). Each case covers a different site type to test the skill's robustness across VuePress/VitePress SPA, GitHub docs, pure HTML, blogs, Chinese knowledge bases, AI/ML docs, Mermaid-heavy sites, and edge-case sites. URLs are verified before creating input.yaml; reference outputs are generated by running the skill per URL.

**Tech Stack:** web-to-local-md skill (Python script + LLM orchestration), YAML for input.yaml, evaluate-skill for quality gate

---

## File Structure

```
data/golden/web-to-local-md/              -- Root (not committed to git)
  README.md                                -- Dataset documentation
  case-01/
    input.yaml                             -- Test input definition
    reference/                             -- Reference output files
  case-02/
    input.yaml
    reference/
  ... (case-03 through case-54)
```

Each `input.yaml` follows evaluate-skill's `--golden` format with extra tags:

```yaml
skill: web-to-local-md
args: "<URL>"
description: "<short description>"
site_type: <type>
language: zh | en
priority: high | medium | low
difficulty: easy | medium | hard
```

```bash
for i in $(seq 1 54); do

  mkdir -p "data/golden/web-to-local-md/case-${nn}/reference"

```

- [ ] **Step 2-54: Run web-to-local-md on each URL**

For each case NN (01 to 54):
1. Read `data/golden/web-to-local-md/case-NN/input.yaml` to get the URL from `args`
2. Invoke: `/good-skills:web-to-local-md <URL>` with `--output-dir data/golden/web-to-local-md/case-NN/reference`
3. If the skill succeeds, the reference output files are in the case-NN/reference/ directory
4. If the skill fails, record the failure — edit input.yaml to add `status: failed` and `failure_reason` fields, leave reference/ empty

**Important:** Run each URL one at a time. Do not batch multiple URLs in a single invocation — the skill processes one site per call. After each run, verify the output before moving to the next case.

- Glob: `data/golden/web-to-local-md/case-NN/reference/*.md` — at least one .md file should exist
- Read one of the .md files — check it's non-empty (> 100 chars), has headings, no placeholder markers
- If images expected: Glob: `data/golden/web-to-local-md/case-NN/reference/images/*` — check images exist
