# learn-domain Skill 设计文档

**日期**: 2026-06-15
**作者**: Claude + Wendymayu
**状态**: 设计完成，待用户审核

---

## 问题陈述

进入新技术领域（如可观测性、AI Agent、LLM）时，工程师需要花费大量时间学习基础知识才能上手项目，学习过程中容易走弯路。核心痛点：

1. **缺乏全局视野**：不了解领域全貌，不知道有哪些子方向、哪些是热点、哪些已过时
2. **理论与实践脱节**：学了理论但不知道怎么用在项目里
3. **资源筛选困难**：搜索结果太多但质量参差不齐，难以分辨哪些值得看
4. **学习顺序混乱**：不知道概念之间的依赖关系，该先学什么后学什么

## 设计决策

**方案选择**: 方案 C（混合方案）—— Claude 知识生成骨架 + WebSearch 定向补充

**理由**: 我们在 research-landscape 实战中观察到 WebSearch 对结构性内容（概念关系、学习路径）不可靠，大量返回合成摘要而非可验证的具体链接。但对"找几篇好入门文章"这种定向搜索，WebSearch 是可用的。方案 C 把两者用到各自擅长的环节：Claude 知识负责"该学什么、怎么学"（准确可靠），WebSearch 负责"哪里有最新好资源"（定向精准搜索）。

## 1. Skill 元信息

**名称**: `learn-domain`

**触发关键词**: "learn", "study", "入门", "上手", "学习路径", "怎么学", "推荐学习路线"

**参数**:
- `<话题>` (必填): 技术领域名称，中文或英文均可（如 "可观测"、"Kubernetes"、"Rust"）
- `--level beginner|intermediate` (可选): 默认根据用户上下文自动判断
- `--project <项目描述>` (可选): 如用户有具体项目目标，反向推导学习路径
- `--lang zh|en` (可选): 默认 `zh`（中文为主 + 英文术语）

**与 landscape 的关系**: 独立 skill，但如果工作目录中存在 `research-landscape-report-*.md` 文件，自动引用其趋势点评数据作为"当前热点"板块。用户也可先运行 landscape 获取热点数据，再运行 learn-domain 获取完整学习路径。

**allowed-tools**: WebSearch, WebFetch, Read, Write, Glob, TodoWrite

## 2. 工作流

| 步骤 | 做什么 | 用什么 |
|------|--------|--------|
| 1. 领域骨架 | Claude 用自身知识生成：概念列表、依赖关系、学习层级、核心术语对照 | 纯知识（无搜索） |
| 2. 定向补充 | WebSearch 搜索每层级的最佳入门资源（每层 3-5 条），获取文章级 URL | WebSearch + WebFetch |
| 3. 热点引用 | 如果存在 landscape 报告，提取其趋势点评作为"当前热点"板块 | Read（读本地文件） |
| 4. 实战建议 | 根据话题 + 用户项目目标，生成 2-3 个实战项目建议（从易到难） | Claude 知识 |
| 5. 生成指南 | 合并所有数据，渲染为结构化 Markdown | Write |

**降级策略**: WebSearch 失败 → 骨架输出仍然完整，资源部分标注 `[链接暂缺，请搜索 <关键词>]` 而不是空着。整体不阻塞。

## 3. 输出结构

生成的 Markdown 报告结构如下：

```markdown
# {话题} 学习指南

## 一、领域全景
- 一句话定义 + 核心子方向列表
- 术语对照表（中文 ↔ 英文）

## 二、概念依赖图
- Markdown 文本层级格式（树状结构）
- 标注每个概念的层级标签和前置依赖

## 三、分级学习路径

### 第一层：基础（估计 X 天，按每个概念约 1-2 天计算）
- 需掌握的概念列表
- 推荐资源（文章级 URL + 一句话推荐理由）

### 第二层：核心（估计 X 天，按每个概念约 2-3 天计算）
- ...同上

### 第三层：进阶（估计 X 天，按每个概念约 3-5 天计算）
- ...同上

## 四、实战项目建议
| # | 项目 | 难度 | 学到的核心概念 | 估计时间 |

## 五、当前热点（可选）
- 引用 landscape 报告的趋势点评
- 如无 landscape 报告：输出"建议运行 /good-skills:research-landscape 补充当前热点"

## 六、避坑指南
- 该领域常见误区（3-5 条）
- 每条附一句话原因
```

## 4. 概念依赖图格式

使用 Markdown 文本层级表示（树状缩进），不用 Mermaid/ASCII art——因为 Markdown 在终端和文件中渲染最稳定。

示例（可观测性领域）：

```
可观测性 (Observability)
├── 信号采集
│   ├── 指标 (Metrics) ← Prometheus          [基础]
│   ├── 日志 (Logs) ← Fluentd/Loki          [基础]
│   └── 链路追踪 (Traces) ← OpenTelemetry   [核心]
│       ├── Span ← 单次操作记录              [基础]
│       ├── Context Propagation ← 跨服务传播 [核心]
│       └── Semantic Conventions ← 统一命名   [核心]
│           └── GenAI SemConv ← LLM追踪标准  [进阶]
├── 数据管线
│   ├── OTel Collector ← 采集/转换/导出      [核心]
│   └── Backends ← Prometheus/Jaeger/Grafana [核心]
└── AI 可观测性 (LLM Observability)
    ├── Token 监控 ← 成本/延迟               [进阶]
    ├── Prompt 追踪 ← 输入/输出审计           [进阶]
    └── Agent 编排追踪 ← 多步推理链路         [进阶]
```

**层级标签规则**:
- `[基础]`: 概念依赖图中最底层、无前置依赖的概念。目标：能读懂该领域的文章和对话。
- `[核心]`: 依赖图中间层、有 1-2 个前置的概念。目标：能独立完成该领域的常规项目。
- `[进阶]`: 依赖图顶层、多个前置的概念 + 当前热点。目标：能做技术决策、理解前沿趋势。

**`--project` 参数影响**: 当用户声明了项目目标，从项目反向推导——标注哪些概念是"必须学"（项目直接依赖），哪些是"可选学"（了解即可），重新调整层级。

## 5. WebSearch 定向补充策略

不每层大规模搜索，而是精准搜索入门级资源：

| 搜索目标 | 搜索关键词 | 数量上限 |
|---------|-----------|---------|
| 第一层基础资源 | `<话题> beginner tutorial guide introduction` | 3-5 条 |
| 第二层核心资源 | `<话题> best practices production practical guide` | 3-5 条 |
| 第三层进阶资源 | `<话题> advanced deep dive architecture internals` | 3-5 条 |
| 中文资源（额外） | `<中文话题> 入门 教程 实践 最佳实践` | 3-5 条 |

**搜索原则**:
- 每层搜 1-2 次，取前 5 条结果，不做深度 WebFetch（不像 landscape 那样逐条验证）
- URL 质量要求：必须是文章级 URL（路径深度 ≥ 1），不能是首页
- 搜索失败不阻塞——骨架仍然完整输出，资源标注 `[链接暂缺，请搜索 <关键词>]`

**避坑指南搜索**: 额外搜 1 次 `<话题> common mistakes pitfalls misconceptions`，补充 1-2 条社区反馈的坑。Claude 知识生成为主。

## 7. 不做的事（YAGNI）

- ❌ 不做交互式问答/测试题（用户没要求，且增加复杂度）
- ❌ 不做进度追踪/学习记录（这是一个生成指南的 skill，不是学习管理系统）
- ❌ 不做视频课程推荐（WebSearch 很难获取视频平台的具体课程 URL）
- ❌ 不做自动更新/定期刷新（指南是一次性生成，用户需要时重新运行）
- ❌ 不做 Mermaid/Graphviz 依赖图渲染（Markdown 文本层级足够清晰）
